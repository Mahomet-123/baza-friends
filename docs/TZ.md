# ТЗ: Единая система «База отдыха «Объект»» (сайт + CRM)

> Источник: обобщение ранних обсуждений проекта (память сессий 2026‑10‑24 / 2026‑10‑25)
> и фактически реализованного прототипа. Документ описывает систему как ЕДИНОЕ целое:
> публичный сайт базы отдыха и внутренняя CRM менеджера работают на одном хранилище.

---

## 1. Цель

Дать владельцу базы отдыха готовый прототип, где:
- гость на **публичном сайте** выбирает объект и оставляет заявку;
- заявка **мгновенно попадает в CRM менеджера** — без сервера, в один клик;
- менеджер в CRM видит заявки с сайта, подтверждает или отклоняет их.

Система работает как **единая**: сайт и CRM — это две точки входа в одни и те же данные.

## 2. Архитектура (прототип)

```
baza-friends/
├── index.html            → публичный сайт (vanilla JS, no bundler, hash-роутинг)
│   assets/js/            → модули в пространстве имён window.BF
│   assets/css/           → BEM-модули (tokens, base, по компонентам, responsive)
└── hostel-booking/       → CRM менеджера (vanilla JS, «локальный бэкенд»)
    app/00-backend.js     → shimSupabase поверх localStorage
    i18n/                 → RU/EN (AR-заготовка)
```

### 2.1 Общее хранилище (ключ связи)
Все данные лежат в `localStorage['hostel_crm_v1']` в виде одного объекта:
```
{ _seq, accounts, session, hostel_members, invites,
  structure, bookings, booking_phones, finance, hostel_settings }
```
Сайт и CRM открываются на **одном origin** (GitHub Pages: `/baza-friends/` и
`/baza-friends/hostel-booking/`), поэтому `localStorage` у них **общий**.

### 2.2 Контракт заявки (site → CRM)
Сайт пишет в `bookings` строку (через `assets/js/crm-bridge.js`):

| поле         | значение                                   | назначение |
|--------------|--------------------------------------------|------------|
| `id`         | `_seq++` (общий счётчик с CRM)             | уникальный id |
| `bed_id`     | `null`                                     | сайт бронирует объект, не койку |
| `guest`      | имя гостя (из формы)                       | кто бронирует |
| `owner`      | `'local'`                                  | CRM читает `bookings` где `owner='local'` |
| `unit_name`  | название объекта                           | показываем в CRM вместо «места» |
| `source`     | `'site'`                                   | пометка «заявка с сайта» |
| `checkin/out`| даты из формы                              | период |
| `price`      | цена объекта за ночь                       | расчёт суммы |
| `paid`       | `false`                                    | оплата не подтверждена |
| `note`       | комментарий гостя                          | примечание |
| `status`     | `'new'`                                    | новая / `confirmed` / `rejected` |
| `adults/kids/guests` | из формы                            | состав гостей |
| `created/updated_at` | ISO-время                          | аудит |

Телефон гостя пишется отдельно в `booking_phones[{booking_id, phone}]`
(так же, как делает CRM для своих броней).

CRM читает эти строки в `cloudLoad()` → `rowToBk()` и показывает в таблице броней,
отображая `unit_name` вместо удалённой «койки» и бейдж **«с сайта»** для `source==='site'`.

## 3. Модель бронирования

```
заявка (site) ──▶ bookings(status='new', source='site')
                        │
            менеджер в CRM: подтвердить / отклонить
                        │
                  status='confirmed' | 'rejected'
```

- Статусы: `new` → `confirmed` / `rejected`.
- Смена статуса происходит в общем store, поэтому видна и в сайт-админке (`#/manager`), и в CRM.

## 4. Контент сайта (прототип)

- **Языки:** RU (основной) + EN. Переключатель в шапке.
- **3 категории объектов** (аккордеон на главной):
  - Номера — 7 шт., от 7 000 ₽/ночь
  - Коттеджи — 5 шт., от 10 000 ₽/ночь
  - 2‑этажные — 3 шт., от 15 000 ₽/ночь
- **Территория:** бассейн, детская площадка, парковка, пляж, беседки, веранда,
  волейбол, Wi‑Fi (карточки-фото с лайтбоксом).
- **Белый лейбл:** название, цвет акцента, контактный телефон задаются в админке
  (`#/manager`, панель настроек) и хранятся в `localStorage['bf_settings']`
  (расчёт на мульти-клиентскую базу в будущем).
- **Ресторан:** отдельная секция-тизер «бронирование столиков — скоро»
  (будущая фича: бронь по времени).

## 5. Функциональные блоки сайта

| блок | модуль | назначение |
|------|--------|-----------|
| состояние + i18n | `state.js`, `i18n.js` | `window.BF`, язык, настройки белого лейбла |
| главная | `home.js` | hero, каталог-аккордеон, территория, CTA |
| страница объекта | `detail.js` | `#/unit/:id` (SEO/шаринг) |
| модалка объекта | `modal.js` | листание объектов категории + кнопка заявки |
| форма заявки | `form.js` | валидация, подсчёт гостей → `BF.submitBooking` |
| галерея/лайтбокс | `gallery.js`, `lightbox.js` | переиспользуемые фото-компоненты |
| админка | `manager.js` | список заявок + настройки белого лейбла |
| **мост к CRM** | `crm-bridge.js` | `submitBooking / listBookings / setBookingStatus` |
| роутинг | `router.js` | hash-роутинг `#/`, `#/unit/:id`, `#/manager` |
| вход | `main.js` | делегирование кликов, старт приложения |

## 6. Как проверить связь (тест)

`scripts/test-linkage.js` (puppeteer-core, headless Chrome):
1. поднимает `python -m http.server 8000`;
2. на сайте открывает форму объекта и отправляет заявку;
3. проверяет, что заявка записалась в `hostel_crm_v1.bookings`;
4. заходит в CRM (любой email/пароль — демо-вход), ждёт загрузки;
5. проверяет, что заявка видна в таблице броней с бейджом **«с сайта»**.

Запуск:
```
NODE_PATH='C:\Users\HP\.workbuddy-ai\binaries\node\workspace\node_modules' ^
  C:\Users\HP\.workbuddy-ai\binaries\node\versions\22.22.2-1\node.exe scripts/test-linkage.js
```

## 7. Что осталось «на будущее» (вне прототипа)

- Реальный бэкенд (Supabase) вместо localStorage-шима — схема уже продумана:
  `properties / unit_categories / units / booking_requests / bookings / site_settings`.
- Мульти-арендность (разные клиенты = разные настройки белого лейбла).
- Бронирование ресторана по времени.
- Уведомления менеджеру (email/telegram) о новой заявке с сайта.
- Админка сайта как полноценный раздел CRM, а не отдельная страница.
