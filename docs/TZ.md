# ТЗ: Единая система «База отдыха «Объект»» (сайт + CRM)

> Актуальная версия: сеанс 2026‑10‑28. Система работает на **реальном Supabase**,
> сайт и CRM — две точки входа в одни и те же данные. Связь — через Supabase Edge
> Functions (общий секрет `SITE_BOOKING_KEY`). Никакого `localStorage` для бронирований.

---

## 1. Цель

Дать владельцу базы отдыха готовый продукт, где:
- гость на **публичном сайте** выбирает объект и оставляет заявку;
- заявка **мгновенно попадает в CRM менеджера** — без своего сервера, в один клик;
- менеджер в CRM видит заявки с сайта, подтверждает или отклоняет их;
- каталог сайта и планировка CRM — **одно и то же**: правишь структуру в CRM,
  сайт перестраивается сам (Option A).

## 2. Архитектура

```
baza-friends/                         → публичный сайт (vanilla JS, no bundler, hash-роутинг)
├── index.html
├── assets/js/                        → модули в пространстве имён window.BF
│   ├── data.js                       → CATEGORIES/UNITS (статич. fallback; перезаписываются из CRM)
│   ├── crm-bridge.js                 → loadStructure / submitBooking / listBookings / setBookingStatus
│   ├── home.js, detail.js, modal.js, form.js, manager.js, main.js …
└── hostel-booking/                   → CRM менеджера (vanilla JS, реальный Supabase)
    ├── app/                          → UI + логика (структура, брони, календарь, цены)
    └── supabase/
        ├── functions/
        │   ├── create-booking/       → POST заявка с сайта + авто-подбор свободной койки
        │   ├── site-bookings/        → GET/POST заявки (админка сайта #/manager)
        │   └── public-structure/     → GET структура CRM + PII-безопасная занятость
        └── DEPLOY.md                 → как задеплоить и настроить секреты
```

Все Edge Functions: **Verify JWT — OFF**, доступ только по заголовку `x-site-key`
(совпадает с секретом `SITE_BOOKING_KEY`). Запись в таблицы — под `service_role`,
поэтому RLS не ослабляется, а анонимный гость в базу не попадает.

### 2.1 Общее хранилище (Supabase)
Таблицы (схема — `hostel-booking/database/supabase-schema.sql` + миграции):
- `structure` (по владельцу, один JSON-документ):
  `{ apartments:[{id, name, number, floor, price, rooms:[{id, name, type, price, beds:[{id, num, name, price}]}]}], buildings, nextId }`
- `bookings` — по строке на бронь: `bed_id` (nullable), `owner`, `guest`, `checkin`,
  `checkout`, `price`, `paid`, `note`, `source` (`'crm'`|`'site'`), `unit_name`,
  `status` (`new`|`confirmed`|`rejected`), `prepaid`, `adults`, `kids`.
- `booking_phones` — телефон гостя отдельно (виден только автору брони).
- `finance`, `hostel_members`, `invites`, `hostel_settings`.

`public-structure` отдаёт структуру + занятость коек как
`{ bedId, checkin, checkout, status }` — **без имён и телефонов** (PII-safe).

### 2.2 Контракт сайт ↔ CRM
| функция | метод | назначение |
|---------|-------|-----------|
| `public-structure` | GET (+ `x-site-key`) | структура CRM + занятость → сайт строит каталог |
| `create-booking` | POST (+ `x-site-key`) | заявка с сайта; `unitId` → авто-койка; `409 no_free_bed` если всё занято |
| `site-bookings` | GET/POST | список заявок + смена статуса для `#/manager` |

Поля заявки `create-booking`: `guest, unitId, unitName, phone, checkin, checkout,
price, prepaid, comment, adults, kids`. Функция находит комнату по `unitId`, берёт
**первую свободную койку** на `[checkin, checkout)` и ставит `bed_id`.

## 3. Модель бронирования

```
заявка (site) ──▶ bookings(status='new', source='site', bed_id=<койка>)
                        │
            менеджер в CRM: подтвердить / отклонить
                        │
                  status='confirmed' | 'rejected'
```
- Статусы: `new` → `confirmed` / `rejected`.
- Койка назначается **сразу** при заявке с сайта (авто-подбор), поэтому
  ограничение `no_overlap` (по `owner + bed_id + daterange`) не даст продать её дважды.
- Если на даты свободных коек нет — сайт блокирует выбор («Занято») и `create-booking`
  вернёт `no_free_bed`.

## 4. Контент сайта

- **Языки:** RU (основной) + EN. Переключатель в шапке.
- **Категории = апартаменты CRM.** Названия берутся из `apartment.name`
  (фактически: «Номера», «Коттеджи», «2‑этажные дома»). Меняешь название в CRM —
  меняется на сайте.
- **Объекты = комнаты CRM.** Каждая комната = 1 номер с 1 спальней. Реальная
  раскладка (15 объектов): апартамент №1 → 7 номеров, №2 → 5 коттеджей, №3 → 3 дома.
- **Цены:** `resolvePrice(апартамент, комната, койка)` — койка → комната →
  апартамент → 7000 ₽. Редактируются в CRM (кнопка «$» в панели корпусов: цена
  апартамента, комнаты или конкретной койки). Цена объекта на сайте = цена комнаты.
- **Занятость в каталоге:** в каталоге есть выбор дат; если на выбранные даты у
  объекта заняты все койки — карточка помечается «Занято» и не открывает форму.
- **Территория:** бассейн, детская площадка, парковка, пляж, беседки, веранда, Wi‑Fi.
- **Белый лейбл:** название, цвет акцента, контактный телефон задаются в админке
  (`#/manager`) и хранятся в `localStorage['bf_settings']` (настройка клиента).
- **Ресторан:** секция-тизер «бронирование столиков — скоро» (будущая фича).

## 6. Как проверить связь (тест)

1. Задеплоить 3 функции и секреты (см. `hostel-booking/supabase/DEPLOY.md`).
2. Открыть сайт → убедиться, что категории/объекты совпадают с CRM
   (проверка: `GET /public-structure` отдаёт те же апартаменты/комнаты).
3. На сайте выбрать даты, оставить заявку на свободный объект.
4. Зайти в CRM (владелец) → бронь видна в календаре с `bed_id` (реальная койка)
   и бейджом «с сайта» / «Новая».
5. Занять все койки объекта на даты в CRM → на сайте карточка становится «Занято»
   и форма блокируется.
6. Автотест `scripts/test-linkage.js` (puppeteer) — открывает форму, шлёт заявку,
   проверяет появление в CRM.

## 7. Что сделано / что осталось

**Сделано:**
- Реальный бэкенд на Supabase (вместо localStorage-шима).
- Связка сайт ↔ структура CRM (Option A): категории = апартаменты, объекты = комнаты.
- Цены по умолчанию 7000 ₽, редактируемые по апартаменту/комнате/койке в CRM.

- 15 реальных объектов (7+5+3) в структуре CRM.
- Авто-подбор свободной койки при заявке с сайта + блокировка «Занято».
