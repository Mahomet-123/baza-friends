# Настройка SMTP для Supabase через Gmail

Эта инструкция поможет настроить отправку писем (подтверждение email, восстановление пароля) с вашего Gmail-адреса через Supabase Auth.

## Зачем это нужно

По умолчанию Supabase отправляет письма со своего адреса (`no-reply@supabase.io`).  
После настройки SMTP письма будут приходить с вашего Gmail, что выглядит профессиональнее и снижает риск попадания в спам.

---

## 1. Подготовка Gmail аккаунта

Для работы через SMTP Google требует включённую двухфакторную аутентификацию и специальный пароль приложения.

### 1.1. Включите двухфакторную аутентификацию

1. Откройте https://myaccount.google.com/ и войдите в свой аккаунт.
2. Перейдите в раздел **Безопасность** (Security).
3. Найдите пункт **Двухэтапная аутентификация** (2-Step Verification).
4. Если она выключена — включите и следуйте инструкциям Google (потребуется телефон).
5. После включения вернитесь на страницу безопасности.

### 1.2. Создайте пароль приложения

1. В разделе **Безопасность** найдите **Пароли приложений** (App passwords).  
   Если пункт не виден, убедитесь, что двухфакторная аутентификация включена, и обновите страницу.
2. Нажмите **Пароли приложений**.
3. При необходимости войдите ещё раз.
4. В поле **Выберите приложение** укажите **Почта** (Mail).
5. В поле **Выберите устройство** выберите **Другое** (Other) и введите имя, например `Supabase`.
6. Нажмите **Создать** (Generate).
7. Google покажет 16-значный пароль в жёлтом поле, например:  
   `abcd efgh ijkl mnop`
8. Скопируйте этот пароль (можно с пробелами или без — Supabase примет оба варианта).

**Важно:** этот пароль отображается только один раз. Сохраните его надёжно.

---

## 2. Настройка SMTP в Supabase

1. Откройте дашборд вашего проекта Supabase.
2. В левом меню выберите **Authentication → Emails**.
3. Перейдите на вкладку **SMTP Settings**.
4. Включите переключатель **Enable custom SMTP**.
5. Заполните поля:

| Поле | Что вводить | Пример |
|---|---|---|
| **Sender email address** | Ваш Gmail-адрес, с которого будут отправляться письма | `mahomet1994@gmail.com` |
| **Sender name** | Имя, которое увидит получатель | `Хостел 24` (или любое) |
| **Host** | SMTP-сервер Gmail | `smtp.gmail.com` |
| **Port number** | Порт для SSL-подключения | `465` |
| **Minimum interval per user** | Оставьте по умолчанию | `60` |
| **Username** | Ваш Gmail-адрес | `mahomet1994@gmail.com` |
| **Password** | 16-значный пароль приложения, созданный в шаге 1.2 | `abcd efgh ijkl mnop` |

6. Нажмите **Save changes**.

Supabase проверит подключение и сохранит настройки. Если возникнет ошибка, проверьте правильность всех полей.

---

## 3. Проверка отправки писем

1. В Supabase перейдите **Authentication → Users → Add user → Create new user**.
2. Введите email, который принадлежит вам (например, ваш второй адрес или тот же Gmail, если хотите проверить).
3. Поставьте галочку **Auto Confirm User** (чтобы не ждать подтверждения) — или оставьте выключенной, если проверяете именно письмо подтверждения.
4. Создайте пользователя.
5. Проверьте почту: должно прийти письмо с адреса, указанного в **Sender email address**.

Если письмо пришло — настройка успешна.

---

## 4. Возможные проблемы и решения

### Письмо не отправляется или ошибка сохранения SMTP
- Убедитесь, что пароль приложения скопирован **полностью**, без лишних пробелов.
- Проверьте, что включена двухфакторная аутентификация.
- Убедитесь, что порт `465` не заблокирован (обычно работает).
- Попробуйте порт `587` с протоколом TLS (но в Supabase для Gmail обычно 465 достаточно).

### Письмо попадает в спам
- Это нормально для новых отправителей. Попросите получателя пометить письмо как «Не спам».
- Для лучшей доставки используйте собственный домен (например, `noreply@yourcompany.com`), но это требует настройки DNS.

### Google блокирует вход
- Убедитесь, что вы используете **пароль приложения**, а не обычный пароль от Gmail.
- Если пароль приложения не работает, удалите его и создайте новый.

---

## 5. Рекомендации

- Для продакшена рассмотрите использование SMTP-сервисов (SendGrid, Mail.ru для бизнеса, Яндекс 360) с собственным доменом.
- Gmail подходит для небольшого объёма писем (до 500 в день для бесплатного аккаунта), но для больших нагрузок лучше специализированный сервис.
- Храните пароль приложения в безопасном месте (например, в менеджере паролей).
